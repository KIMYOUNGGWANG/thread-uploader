## 1. 제품 개요

### 한 줄 요약
나 혼자 쓰는 SNS 운영 비서. 브랜드별 콘텐츠를 **만들고 → 올리고 → 아침에 보고**한다. 나는 보고를 보고 필요한 것만 막거나 처리한다.

### 해결하는 문제
- 지금은 Threads 글만 자동으로 올라간다. 인스타 릴스·유튜브 쇼츠·틱톡·카드뉴스·X도 하고 싶지만 **영상과 카드뉴스를 만드는 일을 못 하겠다** (사용자 발언).
- 영상 레퍼런스를 많이 모았지만 8개 넘는 세션과 3개 프로젝트에 흩어져 있어서, 영상 작업이 매번 처음부터 다시 시작됐다 (Remotion 템플릿 → HyperFrames 실험 → Higgsfield).
- 지금 릴스 템플릿은 "슬라이드 같다", "타로 같다"는 판정을 받아 품질 기준을 못 넘었다 (`docs/design/reels-visual-direction.md`).
- 결과 확인이 대시보드, GitHub Actions 기록, Threads 앱 등에 흩어져 있다.

### 핵심 가치
- **제작까지 자동**: 업로드만 해 주는 도구(Postiz 등)와 달리, 원고·영상까지 만든다.
- **거의 0원**: 매 영상마다 AI 영상 생성을 하지 않는다. 브랜드 스타일 템플릿과 미리 모아 둔 클립 묶음을 돌려써서, 매일 비용은 0원에 가깝다.
- **승인 부담 없음**: 완성되면 정해진 시간 뒤 자동으로 올라가고, 나는 막고 싶은 것만 막는다.

## 2. 사용자

### 주요 사용자
- **누구**: 운영자 본인 1명 **[사용자 결정]**. 남에게 파는 SaaS가 아니다.
- **상황**: 아침에 대시보드를 열어 어젯밤부터 지금까지의 결과와 오늘 할 일을 확인한다.
- **목표**: 브랜드가 늘어도 내 손이 늘지 않게 하는 것.

### 사용자 시나리오
1. 밤사이 시스템이 cosmicpath의 오늘 영상 원고를 쓰고, 클립 묶음에서 훅 클립을 고르고, 영상을 렌더하고, 품질 검사를 통과시킨다.
2. 아침에 대시보드를 열면 "어제 올라간 것 / 오늘 올라갈 것(자동 업로드까지 남은 시간) / 내가 할 일"이 보인다.
3. 영상을 미리 보고, 이상하면 [취소]를 누른다. 아무것도 안 하면 정해진 시간에 릴스·쇼츠·틱톡으로 올라간다.
4. "틱톡 비공개 영상 1개 공개 전환" 같은 할 일이 있으면 폰에서 처리한다.

## 4. 사용자 흐름 (User Flow)

### 핵심 흐름
```
원고 작성 -> 훅 클립 선택 -> 렌더 -> 품질 검사 -> 취소 창(대기) -> 3채널 업로드 -> 아침 보고
```

### 상세 흐름
1. **원고 작성**: 브랜드의 포맷 목록에서 오늘 포맷을 고르고, 원고·화면 문구·채널별 캡션을 만든다. 기존 원고 품질 게이트(`qualityPass`)를 통과해야 다음 단계로 간다.
2. **훅 클립 선택**: 브랜드 클립 묶음에서 분위기 태그가 맞고 최근에 안 쓴 클립을 고른다.
3. **렌더**: HyperFrames 브랜드 템플릿에 원고·클립·BGM(필요하면 내레이션)을 넣어 1080×1920 영상을 만든다.
4. **품질 검사**: 자동 검사(아래 5장)를 통과하지 못하면 업로드하지 않고 보고판에 "실패 + 이유"로 남긴다.
5. **취소 창**: 통과한 영상은 `autoPublishAt`까지 대기한다. 그 전에 취소하면 올라가지 않는다.
6. **업로드**: 릴스·쇼츠는 공개, 틱톡은 비공개(앱 심사 전)로 각 채널에 직접 올린다. Threads를 거치지 않는다.
7. **보고**: 채널별 성공/실패, 남은 대기, 내 할 일이 대시보드에 모인다.

## 5. 성공 기준

- [ ] **1a**: cosmicpath 영상이 하루 1편 이상 사람 손 없이 나오고, 사용자가 보고 "올릴 만하다"고 판정한 영상이 **5편 연속**이다.
- [ ] **1b**: **7일 연속** 릴스·쇼츠가 자동으로 공개되고, 틱톡은 비공개로 올라간다.
- [ ] 영상 1편의 매일 드는 외부 비용이 **0원**이다 (LLM 원고 생성비 제외, 클립 보충은 가끔).
- [ ] **2**: 아침에 대시보드 한 화면만 보면 "잘 올라갔나 / 남은 것 / 내 할 일"을 다른 곳을 열지 않고 알 수 있다.

품질 검사 기준 **[내 판단]**:
- 첫 프레임부터 글자가 보이고, 화면 위 15%·아래 25%(채널 UI 자리)에 핵심 글자가 없다.
- 검은 화면·빈 프레임이 0.3초 넘게 없다.
- 길이는 포맷 정의 범위 안이다 (정지형 6~10초, 설명형 15~30초).
- "슬라이드 같음" 방지: 모든 구간에 배경이나 요소의 움직임이 있다. 레퍼런스 영상(코드깎는노인, bang-motion)에서 쓰는 "슬라이드 말고 영상처럼" 자기 점검 규칙을 따른다.
- (선택) 렌더된 프레임 몇 장을 화면만 보고 평가하는 비평 단계. claude-motion-design 방식이며, 비용이 들면 끈다.

## 6. 안 만드는 것 (Out of Scope)

> 이 목록에 있는 건 Phase 1에서 만들지 않습니다.
> AI에게 코드를 시킬 때 이 목록을 함께 공유하세요.

- **매 영상마다 AI 영상 생성 (Higgsfield·Seedance)** -- 이유: 편당 만 원대라 "거의 0원"과 맞지 않고, 지금 크레딧도 없다. 클립 묶음 교체로만 쓴다.
- **매 영상마다 에이전트가 처음부터 디자인** -- 이유: 레퍼런스 영상 기준 편당 30~50분, API 5~11달러가 든다. 스타일은 브랜드당 한 번만 디자인하고, 매일은 템플릿에 원고만 갈아 끼운다.
- **Threads 경유 교차 발행 확장** -- 이유: 11/17 Threads 글 길이 실험을 오염시킨다. 영상은 각 채널에 직접 올린다.
- **Threads 발행·생성 로직 변경** -- 이유: 같은 실험 동결. Threads 쪽은 건드리지 않는다.
- **남에게 파는 기능 (가입·결제·팀)** -- 이유: 사용자는 본인 1명이다.
- **텔레그램·이메일 알림** -- 이유: 보고는 대시보드에서만 받는다 **[사용자 결정]**.
- **AI 진행자(아바타) 영상** -- 이유: 2026-10-24 보류 결정이 유지된다 (`docs/superpowers/specs/2026-10-24-ai-presenter-reels-design.md`).
- **카드뉴스·X** -- 이유: Phase 3·4에서 한다.
- **예언형 문구, "댓글 달면 해석", 키워드 DM** -- 이유: 기존 브랜드 보이스 금지 규칙이다.
