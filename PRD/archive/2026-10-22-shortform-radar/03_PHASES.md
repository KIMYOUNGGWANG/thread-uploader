# 숏폼레이더 (가칭) -- Phase 분리 계획

> 한 번에 다 만들면 복잡해져서 품질이 떨어집니다.
> Phase별로 나눠서 각각 "진짜 동작하는 제품"을 만듭니다.
> Phase 1은 1a(피드)·1b(생성+결제) 둘로 나눕니다. 1a만으로 무료 공개해 반응을 먼저 봅니다.

---

## Phase 1a: 급상승 피드 (2~3주)

### 목표
로그인하면 주제 탭별로 24시간 내 급상승 쇼츠가 증가속도 순으로 보인다. 매시간 자동 갱신. 무료 공개 가능한 상태.

### 기능
- [ ] 구글·카카오 소셜 로그인, 첫 로그인 시 Organization + Free Subscription 자동 생성
- [ ] 기본 주제 8~10개 + 주제별 시드 채널 시드 데이터 (SQL seed 파일)
- [ ] 수집 크론 ①: 6시간마다 시드 채널 업로드 목록에서 신규 쇼츠 수집 (`playlistItems.list` → `videos.list`로 길이·통계)
- [ ] 수집 크론 ②: 매시간 48h 이내 영상 통계 스냅샷 (`videos.list` 50개씩 배치) → velocity 계산 → Video 캐시 갱신
- [ ] 보관 크론: 30일 지난 스냅샷·7일 지난 영상 삭제 (YouTube API 약관)
- [ ] 피드 화면: 주제 탭 · 국내/해외 토글 · 24h/48h 토글 · 카드 그리드 (섬네일·조회수·N시간 전·채널·좋아요·댓글·증가속도 배지)
- [ ] 영상 상세: 유튜브 임베드 + 조회수 추이 그래프 + "벤치마킹 생성" 버튼(1b 전까지는 "곧 출시")
- [ ] 랜딩 페이지 (대기자 이메일 수집 포함)

### 데이터
- Organization, User, Subscription(free 고정), Topic, Channel, Video, VideoSnapshot

### 인증
- Supabase Auth 소셜 로그인 (Google, Kakao)

### "진짜 제품" 체크리스트
- [ ] 실제 DB 연결 (목업 데이터 X)
- [ ] 실제 인증 (하드코딩된 비밀번호 X)
- [ ] 실제 서버에 배포 (localhost X)
- [ ] 다른 사람이 URL로 접속해서 써볼 수 있음
- [ ] 크론이 24시간 돌아간 뒤 피드에 영상이 실제로 채워져 있음
- [ ] 하루 YouTube 쿼터 사용량이 10,000 미만 (Google Cloud 콘솔로 확인)

## Phase 1b: 클라이언트 + 벤치마킹 생성 + 결제 (2~3주)

### 전제 조건
- Phase 1a가 배포돼 피드가 매시간 채워지고 있음

### 목표
클라이언트를 등록하고, 피드의 영상 하나를 골라 그 계정 버전 스크립트·촬영컷을 뽑고, 한도가 차면 결제해서 늘릴 수 있다. 돈 받기 시작.

### 기능
- [ ] 클라이언트 CRUD (이름·핸들·플랫폼·주제·톤·금지어·메모), 플랜별 개수 제한
- [ ] 자막 추출: 유튜브 자막 트랙 가져와 Transcript 캐시. 자막 없으면 "생성 불가" 안내 (Whisper는 미결)
- [ ] 벤치마킹 생성: Claude API 호출 → 원본 분석 / 스크립트 / 촬영컷(JSON) → Generation 저장 → 화면 표시 + 마크다운 복사
- [ ] 생성 이력 (클라이언트별 목록)
- [ ] 월 구독: 토스페이먼츠 빌링키 정기결제, 플랜 Free/Pro/Team, 월 사용량 리셋, 업그레이드 모달
- [ ] 랜딩에 요금표

### 데이터
- 추가: Client, Transcript, Generation. Subscription에 toss_billing_key·gen_used 활성화

### "진짜 제품" 체크리스트
- [ ] 실제 토스 결제(테스트 키)로 결제 → 한도 상향 → 다음 달 자동 결제까지 흐름 확인
- [ ] 생성 15초 이내, 실패 시 사용량 차감 안 됨
- [ ] 다른 조직의 클라이언트·생성 결과가 절대 보이지 않음 (RLS 테스트)

### Phase 1b 시작 프롬프트
```
이 PRD를 읽고 Phase 1b를 구현해주세요.
@PRD/01_PRD.md
@PRD/02_DATA_MODEL.md
@PRD/04_PROJECT_SPEC.md

Phase 1b 범위:
- 클라이언트 CRUD
- 자막 추출 + Transcript 캐시
- 벤치마킹 생성 (Claude API) + 생성 이력
- 토스페이먼츠 월 구독 + 플랜 한도

반드시 지켜야 할 것:
- 04_PROJECT_SPEC.md의 "절대 하지 마" 목록 준수
- RLS로 조직 격리, 서버에서 한도 검사
- 빌링키는 암호화 저장, 결제 콜백은 서명 검증
```

## Phase 2: 확장 (3~4주)

### 전제 조건
- Phase 1b 배포 + 유료 고객 1곳 이상

### 목표
에이전시가 자기 주제를 만들고, 인스타 릴스까지 같은 피드에서 본다.

### 기능
- [ ] 커스텀 주제 (내 키워드·채널 추가, 조직 전용)
- [ ] 저장 보드 + 메모
- [ ] 인스타 릴스 수집 (Apify actor) → Video.platform 컬럼 추가, 플랫폼 탭
- [ ] 생성 재생성·수정·내보내기 (노션/구글독 복사)
- [ ] 자막 없는 영상 Whisper 전사 (비용 측정 후)

### 추가 데이터
- Board, BoardItem, Topic.org_id 활성화, Video.platform

### 통합 테스트
- Phase 1 피드·생성·결제가 여전히 정상 동작하는지 확인
- Apify 월 비용이 Pro 플랜 매출보다 작은지 확인

---

## Phase 3: 고도화 (기간 미정)

### 전제 조건
- Phase 1 + 2가 안정적으로 운영 중, 유료 고객 10곳 이상

### 목표
사람이 안 들어가도 매일 아침 클라이언트별 추천이 도착한다.

### 기능
- [ ] 클라이언트별 일간 다이제스트 (이메일·카카오 알림톡)
- [ ] 팀원 초대·권한 (owner/member)
- [ ] 주제 자동 태깅 (시드 채널 밖 영상도 LLM으로 분류)
- [ ] 틱톡 수집, 영어권 주제

### 주의사항
- 알림톡·Whisper·Apify 모두 건당 비용. 플랜 한도에 반영 필요
- 자동 태깅은 LLM 호출이 수천 건/일이 될 수 있어 배치·캐시 설계 필수
