# 뉴스 데스크 -- PRD

> 2026-11-19. 표기: **[사용자 결정]** = 사용자가 정한 것, **[내 판단]** = 설계자가 정한 것

## 1. 제품 개요

### 한 줄 요약
기사 하나를 넣으면 팩트를 뽑고, 플랫폼별 원고를 만들고, 내가 승인한 것만 여러 채널에 한 번에 내보내는 데스크.

### 해결하는 문제
- 뉴스 하나를 채널마다 따로 다듬고 따로 올리느라 손이 많이 간다.
- AI가 쓴 뉴스 글은 원문에 없는 숫자·사실을 섞을 수 있다. 근거를 같이 봐야 안심하고 올릴 수 있다.
- 지금 대시보드의 "이 뉴스로 스레드 생성"은 프롬프트 문장이 그대로 본문이 되는 상태라 실제로는 못 쓴다 (`src/components/NewsTrendingTab.tsx`, `Dashboard.tsx`의 `handleUseNewsForDraft`).

### 핵심 가치
- **근거가 보이는 팩트**: 팩트마다 원문 인용을 붙이고, 인용이 원문에 실제로 있는지 기계로 확인한다.
- **승인한 글만 나간다**: 플랫폼마다 승인하고, 승인 뒤 고치면 승인이 풀린다.
- **한 번 누르면 여러 채널**: 텔레그램·Threads는 자동, 자동이 안 되는 카카오는 복사 모드.

## 2. 사용자
- 운영자 본인 1명 **[사용자 결정]**. 팔지 않는다. 대표 콘텐츠(콘텐츠 플라이휠)용이다.
- 상황: AI·자동화 뉴스를 보고 내 채널들에 빠르게 정리해 올리고 싶을 때.

## 3. 핵심 기능 (Phase 1)
| 기능 | 설명 |
|---|---|
| 기사 수집 | URL을 넣으면 본문을 긁어 온다. 못 읽으면 원문 붙여넣기 |
| 원문 그대로 모드 | AI 가공 없이 원문을 그대로 원고로 |
| 팩트 + 근거 | 팩트마다 원문 인용, 원문에서 확인됨/못 찾음 표시. 원고에 원문에 없는 숫자가 있으면 경고 |
| 플랫폼별 원고 | 텔레그램·Threads·카카오 탭, 글자 수와 한도 표시 |
| 승인 | 플랫폼별 승인, 일괄 승인, 수정하면 승인 풀림(Rev 증가) |
| 이미지 | 최대 5장, Ctrl+V·드래그·선택, 순서 = 전송 순서 |
| 발행 | 텔레그램 채널·Threads 자동, 카카오 복사 → "보냈어" |
| 상태 | 대기/올라가는 중/완료(링크)/실패(사유), 대기 취소, 실패 후 잠금 해제 |

## 4. 사용자 흐름
1. 브랜드 대시보드 헤더의 "뉴스 데스크"로 들어간다.
2. URL 또는 원문, 메모, 이미지를 넣고 [원고 만들기].
3. 팩트와 근거를 보고, 탭마다 원고를 고치고 승인한다.
4. [발행]을 누르면 승인된 플랫폼만 나간다. 카카오는 복사해서 단톡방에 붙여 넣고 [보냈어].

## 5. 성공 기준
- 실제 기사 URL로 1분 안에 팩트·원고가 나온다.
- 테스트 텔레그램 채널에 글만 / 1장 / 3장 발행이 된다.
- 두 탭에서 동시에 눌러도 같은 기사가 한 플랫폼에 두 번 나가지 않는다.
- 승인 안 한 글·이미지는 나가지 않는다.

## 6. 안 만드는 것 (Out of Scope)
- **카카오 단체방·오픈채팅 자동 전송** -- 공식 API가 없고 자동화는 카카오 정책 위반이다 (카카오 데브톡 공식 답변). 복사 모드로 대신한다. **[내 판단]**
- **페이스북 개인 피드** -- 2018년 `publish_actions` 폐지로 불가. Phase 2에 페이스북 페이지로 대체한다. **[내 판단]**
- **기존 Post 테이블로 Threads 발행** -- X 크로스포스트·카드뉴스·autopilot·실험 집계로 새어 나간다. 배포 엔진 어댑터로 따로 보낸다. **[내 판단]**
- **텔레그램 알림** -- 상위 PRD의 "텔레그램·이메일 알림 제외"는 그대로다. 여기서 추가하는 건 알림이 아니라 *발행 채널*이다.
- **판매용 기능(가입·결제)** -- 상위 PRD와 같다.
