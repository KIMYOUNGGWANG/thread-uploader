# 길이 실험 실행 기능 설계 (cosmicpath)

사전 등록 문서: `docs/experiments/2026-10-16-post-length.md`
이 문서는 그 실험을 실제로 돌리는 데 필요한 생성·발행 변경을 다룬다. 가설, 배정 시퀀스, 글 수, 판정 기준은 사전 등록 문서가 기준이고, 여기서 바꾸지 않는다.

## 왜

- 사용자는 "짧은 글(260자 이하)" 방침을 스크립트, 캠페인, 발행 게이트까지 모든 경로에 강제하기 전에 인과 근거를 원한다.
- 관찰 데이터에서는 짧은 글의 도달이 1.54배 [1.25, 3.01]였다. 하지만 시기, 주제, 공식과 섞여 있어서 원인을 확정할 수 없다.
- 생성 프롬프트는 6월부터 이미 220자를 목표로 한다. 그래서 이 실험의 실제 비용은 4주 동안 일부러 긴 글 45개를 발행하는 것이다. 사용자는 이 도달 손해를 감수하기로 했다.

## 목표

- 미리 정한 S/L 시퀀스 90칸(S 45, L 45)을 사람 손 없이 발행 순서대로 지킨다.
- 맞는 길이 초안이 없어서 슬롯이 비는 일을 줄인다. 발행 리듬 목표는 "생성 용량" 절의 결정을 따른다.
- 실험이 끝나면(90칸 소진) 생성과 발행이 저절로 평소 동작으로 돌아간다.
- 판정은 기존 `scripts/analyze-post-response.mjs --experiment` 모드로 한다.

## 하지 않을 것

- cosmicpath-global을 포함한 다른 브랜드에는 영향을 주지 않는다.
- 주제, 공식, 링크, 발행 시간 선택 로직은 바꾸지 않는다. 길이만 처치다.
- 중간 결과를 보여주는 대시보드나 알림은 만들지 않는다. 중간 확인을 막는 게 목적이다.
- DB 스키마와 마이그레이션은 건드리지 않는다.

## 실패로 칠 것

- 사람이나 큐 순서가 S/L을 골라서 무작위 배정이 깨지는 것
- 긴 글이 길이와 무관한 이유로 체계적으로 탈락해서, 살아남은 긴 글만 발행되는 것(선택 편향)
- 실험 로직이 실험 종료 후나 다른 브랜드에서 동작하는 것

## 운영 전제 (사용자 확인)

- 사용자는 4주 동안 cosmicpath 글을 직접 고치거나 수동으로 발행하지 않는다.
- 결과적으로 리뷰 대기(NEEDS_REVIEW) 초안은 사실상 발행되지 않는다.
  - 실험 글은 자동 승인 공식(`isAutopilotFormula`)에서 나온 PENDING 초안으로만 채워진다.
  - 홍보·영상 글도 NEEDS_REVIEW로 생기니까 발행되지 않는다(`promo-post-service.ts:64`, `video-jobs/complete/route.ts`).
- **시작 전제(내 판단):** 이 기능과 PR #5가 main에 머지·배포된 뒤에 시작한다.
  - PR #3(발행 게이트)과 #4(학습 루프)도 시작 전에 머지하기를 권한다. #4는 자동 승인 공식, 즉 실험 공급원을 바꾸니까 실험 도중에 바뀌지 않게 하려는 거다.
  - 실험 중의 다른 코드 변경은 막지 않는다. S/L이 2칸 블록으로 시간상 고르게 섞여 있어서, 도중에 생긴 변화는 두 그룹에 똑같이 영향을 준다.
  - 예외는 길이와 상호작용하는 변경(길이 감점, 길이 지시문)이다. 이런 변경은 실험 중에 하지 않는다.

## 정의

- **실험 대상 글:**
  - cosmicpath 브랜드
  - `postCategory === "GROWTH"`
  - `formulaId`가 `video:`로 시작하지 않음(홍보 영상 글 제외)
  - 카드 캐러셀 이미지가 붙은 글은 포함한다. 생성기가 만드는 한국어 글은 모두 카드가 붙기 때문이다.
- **실험 밖 글:** WARMUP, 홍보 영상(`video:`), 그 외 대상 조건에 맞지 않는 글
  - 평소처럼 발행된다.
  - 시퀀스를 소비하지 않는다.
  - 판정에서도 제외한다.
- **길이 등급:** `content.length`(공백, 줄바꿈 포함 JS 문자열 길이) 기준
  - S: ≤260
  - L: ≥390
  - 중간(261~389): 실험 중 발행하지 않는다.
- **실험 초안(내 판단):** `createdAt ≥ startAt`인 실험 대상 초안만 실험 슬롯에 쓴다.
  - 시작 전에 만든 초안은 길이 목표나 감점 조정 없이 만들어졌으니까, 실험 중에는 발행하지 않고 큐에 남겨둔다.
  - 실험이 끝나면 평소처럼 발행된다.
  - 종료 후 남은 실험 L 초안도 평소처럼 발행된다. 몇 개 정도의 긴 글이 더 나가는 건 감수한다.
- **시퀀스 위치:** `startAt` 이후 발행된 실험 대상 글 중 S 또는 L인 글의 수. DB에서 매번 다시 센다. 따로 저장하는 카운터는 없다.
- **실험 표본:** `startAt` 이후 발행 시각 순으로 처음 90개의 실험 대상 S/L 글. 종료 후 발행된 글은 섞이지 않는다.

## 설계 (결정된 부분)

### 1. 실험 상태: `brandConfig.lengthExperiment` (JSON, 스키마 변경 없음)
- **필드:** `startAt`(ISO), `sequence`(S/L 90자 문자열, 사전 등록 문서의 표와 동일), `shortMax: 260`, `longMin: 390`
- `BrandConfig` 타입과 파서에 추가한다. 값이 없거나 형식이 틀리면 실험이 꺼진 것으로 본다.
- **켜져 있는 조건:** `lengthExperiment`가 있고, `now ≥ startAt`이고, 시퀀스 위치 < 90.
- **시작 방법:** 작은 스크립트로 cosmicpath `brandConfig`에 위 값을 써넣는다(멱등).
  - 운영 DB 쓰기라서 실행은 사용자 승인 후에 한다.
  - `startAt`은 실행 시각이다. 실행 후 사전 등록 문서의 `시작일` 칸에 기록한다.
- 테스트로 시퀀스 문자열이 사전 등록 문서의 표와 일치하는지 확인한다.

### 2. 발행: 시퀀스가 슬롯의 길이를 정한다 (`/api/cron/publish`)
- 실험이 켜져 있으면 지금 슬롯의 등급은 `sequence[시퀀스 위치]`다.
- **후보 선택:** 기존 조건(PENDING, `scheduledAt ≤ now`, `qualityPass`, `scheduledAt` 오름차순)을 그대로 쓰고, 다음 글은 건너뛴다.
  - 실험 대상이면서 길이 등급이 지금 슬롯과 다른 글
  - 실험 대상이면서 중간 길이인 글
  - 실험 대상이면서 `startAt` 전에 만든 글
  - 실험 밖 글은 건너뛰지 않는다. 다만 실험 밖 글(홍보·영상)은 NEEDS_REVIEW로 생기고 리뷰가 없으니 실제로 슬롯을 차지할 일은 거의 없다. 사람이 승인하면 시퀀스를 소비하지 않고 발행된다.
- **후보가 없으면** 이번 슬롯은 건너뛰고 `skipped` 사유를 `length_experiment_waiting_S` 또는 `length_experiment_waiting_L`로 남긴다. 다른 등급 글로 대신 채우지 않는다.
- shadowban 모드(WARMUP 우선 경로), 쿼터, 안전 게이트는 지금 그대로 둔다.
- 수동 발행 API(`/api/posts/[id]/publish`)는 바꾸지 않는다. 사용자가 4주 동안 쓰지 않기로 했다.

### 3. 생성: 큐에 두 등급을 모두 채운다 (`generatePostsForBrand`)
- 실험이 켜져 있으면 만드는 초안마다 목표 등급을 정한다.
  - 기준: 큐에 있는 PENDING + `qualityPass` 실험 대상 초안 중 S와 L 개수를 보고 부족한 쪽을 먼저 채운다.
  - 같으면 다음 시퀀스 칸의 등급을 따른다.
- **프롬프트 목표 길이:** 지금의 "220자 내외(140~240자)" 줄을 등급별 목표로 바꾼다. 이 줄은 `generate-posts.ts:490`, `:586` 두 곳에 있다.
  - S: 지금 문구 그대로(140~240자)
  - L: 400~450자. 알고리즘 점수가 450자 초과에 −4점을 주니까 그 아래로 잡는다. 한 개 포스트 한도(500자) 안이라 스레드로 쪼개지지도 않는다.
- **공식 지시문 속 길이 문구(내 판단):** 일부 공식에는 "140~200자"가 박혀 있다(`domain-registry.ts:91`, `:118`). 이대로면 그 공식은 L에서 거의 다 탈락해서, 두 그룹의 공식 구성이 달라진다.
  - 실험 초안 프롬프트에는 "길이는 이 지시가 공식 지시문보다 우선한다"는 줄을 넣는다.
  - 공식 지시문 자체는 고치지 않는다.
- **길이 검증과 재시도(내 판단):** 알고리즘 리메디에이션(재작성)까지 끝난 최종 본문의 길이 등급이 목표와 다르면, 같은 공식·같은 목표 등급으로 최대 2번 다시 만든다. 그래도 다르면 버리고 `failureReasons`에 사유를 남긴다.
  - 버리는 대신 재시도하는 이유: 공식별 탈락률 차이 때문에 S와 L의 공식 구성이 벌어지는 걸 줄이려는 거다.
- **refill backlog(내 판단):** 실험 중 cosmicpath refill은 backlog를 "PENDING 실험 초안의 S·L 개수"로 센다.
  - 지금은 리뷰되지 않는 NEEDS_REVIEW까지 backlog에 세서 약 1주 안에 `backlog_full`로 생성이 멈춘다. 그리고 S가 쌓여 있으면 L이 만들어지지 않는 교착이 생긴다.
  - 등급별로 목표치의 절반을 채울 때까지 부족한 등급을 만든다.
- 실험이 꺼져 있으면 지금과 똑같이 동작한다.

### 3-1. 생성 용량 (사용자 결정: 하루 2~3회 refill, LLM 비용 증가 감수)
- **지금 용량:** refill은 하루 1회, 한 번에 최대 6개다. 5분 실행 시간 한도 때문이다(`queue-refill.ts:2`, `refill.yml`).
- **필요 용량:** 실험 글은 자동 승인 공식에서만 나오고, 길이·품질·알고리즘 단계에서 일부가 버려진다. 그래서 하루 6개 생성으로는 하루 3개 이상 발행을 보장할 수 없다.
- **결정:** 실험 기간 동안 refill을 하루 3회 돌린다. 발행 리듬 목표는 평소(최근 주당 약 23개)에 가깝게 유지하는 것이다.
- **방법(내 판단):** `refill.yml`에 실행 시각 2개를 추가한다(기존 KST 07:13 + 약 8시간 간격).
  - 한 번에 최대 6개 한도는 실행 시간 때문이라 그대로 둔다.
  - refill은 목표치까지의 부족분만 만드니까, 같은 워크플로를 쓰는 다른 브랜드의 총 생성량은 거의 늘지 않는다. 더 자주 채워질 뿐이다.
  - 추가한 시각에는 "길이 실험용, 실험 종료 후 제거" 주석을 단다. 종료 후 제거는 수동 작업이다.

### 4. 길이만으로 매기는 감점은 실험 대상 초안에서 끈다
- 전문가 패널의 타깃 유저 평가가 한국어 280자 초과에 −10점을 준다(`expert-panel-evaluator.ts:150`, fold 규칙). 이 점수가 품질 게이트 통과에 들어간다(`quality-gate.ts:425`).
  - 품질 게이트에서 떨어진 초안은 두 번 재시도한 뒤 버려진다(`generate-posts.ts:344-353`).
  - 그래서 L 초안이 길이 때문에 더 자주 버려진다. 특히 분류·저장 유도 단어가 없는 공식의 L 초안이 떨어진다.
  - 결과적으로 L 공급이 줄고, 살아남은 L의 공식 구성이 치우치는 선택 편향이 생긴다.
- **조치:** 실험이 켜져 있을 때 생성되는 cosmicpath 초안에는 이 fold 감점을 적용하지 않는다. 다른 품질 검사는 모두 그대로 둔다.
- 알고리즘 점수의 450자 초과 감점은 L 목표(≤450)로 피하니까 손대지 않는다.

### 5. 판정 스크립트 정합성 (`scripts/analyze-post-response.mjs --experiment`)
- 판정 대상을 위의 실험 대상 정의와 맞춘다. GROWTH가 아닌 글과 `video:` 공식 글을 제외한다.
- `--from`에는 `startAt`을 쓴다.
- **상한 추가:** 지금은 `>= from` 조건만 있어서(`analyze-post-response.mjs:194`) 종료 후 발행된 글이 섞인다. 위의 "실험 표본"(처음 90개)으로 자른다. 사전 등록 문서의 판정 절차에도 이 컷오프를 명시한다. 가설과 판정 기준은 바꾸지 않는다.
- **진단 출력(내 판단):** 판정 때 S·L별 공식 구성을 함께 출력한다. 두 그룹의 공식 구성이 크게 다르면 결과 해석에 주의하라는 근거로 쓴다.

## 빌더에게 맡기는 것

- 시퀀스 위치 계산, 후보 필터, 목표 등급 결정을 어느 파일의 어떤 함수로 둘지. 단, 발행·생성·판정이 같은 "실험 대상" 정의를 공유해야 한다.
- 발행 후보를 DB 쿼리로 거를지, 상위 N개를 가져와서 메모리에서 거를지
- fold 감점을 끄는 신호를 품질 게이트까지 어떻게 전달할지
- 테스트 구성. 최소한 아래 경우는 필요하다.
  - 시퀀스 문자열이 사전 등록 문서와 일치
  - 발행이 슬롯 등급에 맞는 글만 고르고, 없으면 건너뜀
  - 실험 밖 글은 시퀀스를 소비하지 않음
  - 90칸이 끝나면 평소 동작으로 돌아감
  - 생성의 목표 등급 배정, 같은 공식 재시도, 길이 불일치 초안 폐기
  - 실험 중 refill backlog 계산
  - 시작 전에 만든 초안을 건너뜀
  - 판정이 처음 90개에서 자름
  - 다른 브랜드는 영향 없음

## 남는 위험 (알고 감수함)

- **공급 부족:** 자동 승인 공식에서만 PENDING이 나오니까, L 초안이 품질 게이트에서 더 자주 떨어지면 L 슬롯이 비어 실험이 늘어질 수 있다. `length_experiment_waiting_*` 사유로 확인할 수 있다.
- **학습 루프 영향:** 실험 중에도 학습 루프는 돈다. 길이가 공식과 무관하게 배정되니까 공식 평가에 체계적인 편향은 없지만, 노이즈는 커진다.
