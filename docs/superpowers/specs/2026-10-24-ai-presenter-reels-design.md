# AI 진행자 릴스 포맷 (`ig_talk`) — 설계

- 날짜: 2026-10-24
- 브랜드: cosmicpath (한국어 인스타 릴스)
- 상태: **보류** (2026-10-24, 사용자 결정. 다음 재개는 0단계 샘플 1편부터. 서비스는 HeyGen 추천, 아직 미정)
- 출발점: 사용자가 공유한 "릴스 공장" 글(터진 릴스 분석 → 공식대로 원고 → AI 진행자 촬영 → 편집). 이 문서는 그중 **AI 진행자 촬영** 조각만 다룬다. 다른 계정 릴스 자동 수집은 범위 밖이다.

## 1. 왜 만드나

- 지금 릴스는 두 포맷(랭킹 정지 `ig_rank_10s`, 카드 선택 `ig_pickcard_16s`) 모두 이미지와 카드만 나오고, 말하는 사람이 없다.
- 경쟁 계정 관찰(`docs/experiments/2026-10-22-ig-reels-format.md`)에서 "말하는 영상"은 두 번 나왔다. gold_pepper_(중앙값 대비 최대 ×60, 30~90초), dohwadore_life_reader(×4, 41~55초)다. 사람이 말하는 포맷은 권위와 신뢰를 만들기 쉽고, 저장보다 **프로필 클릭과 상담·리포트 전환** 쪽으로 이어질 가능성이 있다.
- 실제 사람을 매번 찍을 수 없으니 AI 진행자로 대신한다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 같은 얼굴의 진행자 한 명이 한국어로 20~30초 동안 사주 이야기를 하는 9:16 릴스를, 한 편당 사람 손이 원고 승인 1번과 영상 승인 1번만 가는 흐름으로 만든다.
- 만든 릴스는 기존 경로(승인 대기 → Threads 발행 → 인스타 자동 교차 발행)를 그대로 탄다. 발행 쪽 코드는 새로 만들지 않는다.
- 첫 6편의 숫자를 기존 실험 장부와 같은 열(views, saves, profileClicks, landingClicks, conversions)로 남긴다.

**비목표**
- 다른 계정 릴스 자동 수집과 분석 (다음 조각)
- 완전 무인 자동화 (11/17 길이 실험 판정 전까지 렌더 자동화는 동결이다. `render-video.yml` 주석 참고)
- cosmicpath-global(영어) 버전
- 진행자 음성·얼굴을 실제 인물과 닮게 만드는 것

**실패 조건 (작동해도 실패로 본다)**
- 진행자가 **실제 사람인 척**하는 것. 캡션 첫 줄이나 화면에 AI 진행자라는 표시가 없는 것.
- 원고와 다른 말을 하거나, 한국어 발음·입 모양이 어색해서 첫 3초에 이탈을 부르는 것
- "댓글 남기면 DM", "댓글 달면 해석", 자동 DM. 실험 문서와 플레이북 reject 목록 그대로다.
- 예측·단정형 문구("올해 반드시 ~된다"). 기존 품질 게이트 기준과 같다.
- 진행 중인 릴스 포맷 실험(랭킹 vs 카드 12편)의 판정을 오염시키는 것

## 3. 제약

- **비용:** Higgsfield `marketing_studio_video` 기준 15초 720p는 75크레딧, 30초 1080p는 390크레딧이다(`higgsfield generate cost`로 2026-10-24 확인). 현재 잔액은 0.26크레딧이라 **충전 없이는 샘플 1편도 못 만든다.**
- **새 라이브러리 없음:** Higgsfield CLI(`higgsfield`)는 이미 설치돼 있고, Remotion·`@remotion/captions`도 이미 있다. 외부 API를 새로 붙이지 않는다.
- **인스타 하루 1편:** `instagram-reels-sync.ts`는 브랜드당 KST 하루 1개만 올린다. 실험 릴스와 같은 날에 올리면 하나는 다음 날로 밀린다.
- **비밀값:** Higgsfield 인증은 CLI 로그인 세션(`higgsfield auth login`)을 쓴다. 키를 코드나 `.env`에 넣지 않는다.

## 4. 흐름 (정해진 부분)

```
원고 작성(Claude, 사람 승인)
  → Higgsfield로 진행자 클립 생성 (로컬 CLI, 9:16, 음성 포함)
  → Remotion IgReels 프레임에 얹기 (진행자 영상 배경 + 문장 단위 자막 + 하단 브랜드)
  → video/scripts/queue-reels.mjs (format: "ig_talk")
  → 대시보드 승인 → publish cron → Threads → instagram-publish cron → 릴스
```

- **진행자:** Higgsfield Marketing Studio의 preset 아바타 중 하나를 고정해서 매 편 같은 얼굴로 간다. 고르는 건 샘플 단계에서 사용자가 한다.
- **원고 구조 (20~30초):** 0~2초 훅 한 문장(질문 또는 의외의 사실) → 본문 3문장(일간이나 상황별로 하나씩 구체적으로) → 마지막 한 문장은 저장 유도("저장해 두고 11월 끝에 다시 보기")와 프로필 링크 언급. 원고 문구는 실험 문서처럼 이 저장소의 docs에 원본으로 남긴다.
- **자막:** 기존 `Captions.tsx`의 문장 단위 SRT를 쓴다. 단어 단위 싱크는 하지 않는다.
- **포맷 ID:** 장부용 라벨 `ig_talk`. 코드에는 `queue-reels.mjs` manifest의 `format` 값으로만 들어간다(기존 두 포맷과 같은 방식).

## 5. 단계

**0단계 — 샘플 1편 (스파이크, 버리는 코드)**
- 크레딧 충전 후 15초 720p로 1편을 만든다(약 75크레딧).
- 확인할 것 세 가지: ① 한국어 원고를 그대로 말하는가 ② 입 모양과 발음이 3초 안에 어색하지 않은가 ③ preset 아바타 중 cosmicpath 톤(차분, 신뢰)에 맞는 얼굴이 있는가
- 하나라도 실패하면 대안을 검토하고 이 문서를 고친다. 대안은 Higgsfield에서 무음 진행자 클립을 만들고, 음성(`seed_audio` 또는 다른 TTS)을 따로 만들어 립싱크하는 방식이다.
- 0단계를 통과해야 1단계로 간다.

- 0단계 결과에 따라 생성 단계 수가 달라진다(한 번에 말하는 클립이냐, 무음 클립 + 음성 + 립싱크냐). 그래서 **1단계의 상세 계획은 0단계 결과를 이 문서에 적은 뒤에 쓴다.** 지금 쓰는 구현 계획은 0단계까지만이다. (작성자 판단)
- 참고: `marketing_studio_video`에는 대사 전용 칸이 없다. `prompt`와 `generate_audio`(기본 false)만 있어서, 원고를 프롬프트 안에 넣고 `generate_audio true`로 시험한다.

**1단계 — 반자동 제작 (6편)**
- 클립 → 렌더 → 대기열 등록을 로컬 명령 하나로 묶는 스크립트를 만든다(`video/scripts/` 아래). 사람은 원고 승인과 대시보드 영상 승인만 한다.
- 원고는 스크립트가 쓰지 않는다. Claude Code 대화에서 쓰고 사용자가 승인한 원고를 docs 원본 파일에 적는다. 스크립트는 그 파일을 입력으로 받는다. 기존 릴스 실험과 같은 방식이고, 렌더 자동화 동결과도 맞다. (작성자 판단)
- `promo-post-service.ts`는 날짜 하나에 한 편만 받고(`video:promo:${date}`), 인스타는 하루 1편이다. 그래서 manifest 날짜는 아래 8절의 일정 규칙에 맞춰 사람이 적는다.
- 6편을 올리고 7일 뒤 숫자를 장부에 적는다.

**2단계 — 판정 후 결정** (이 문서 범위 밖)
- 숫자가 좋으면 자동화(렌더 동결 해제 후 cron)와 경쟁 릴스 수집을 다음 기능으로 기획한다.

## 6. 측정과 판정

- 장부는 `docs/experiments/` 아래에 새 문서로 만든다. 열은 기존 릴스 실험과 같다.
- 비교 기준은 기존 두 포맷의 중앙값이다. 노이즈 기준(2배 이하 차이는 운과 구분 불가)도 기존 실험을 따른다.
- 판정은 6편째가 올라가고 7일 뒤에 한 번만 한다.

## 7. 빌더에게 맡기는 것

- Remotion에서 진행자 영상의 소리를 살리는 방법. 지금 `IgReels`는 오디오가 비어 있고 BGM만 있다.
- SRT 문장 시간은 원고 글자 수 비율로 나누는 정도면 충분하다.
- 스크립트 인자와 출력 경로 이름
- 클립 길이가 원고보다 짧거나 길 때의 처리 (다시 생성할지, 잘라낼지)

## 8. 사용자 결정이 필요한 것

1. **일정 (사용자 결정, 2026-10-24):** 랭킹 vs 카드 실험이 진행되는 동안 **실험 릴스가 없는 날에만** 올린다. 실험 릴스의 요일과 시간대는 건드리지 않는다. 비교 기준은 판정 시점까지 쌓인 실험 릴스의 중앙값이다.
2. **크레딧:** 0단계 충전 금액과 1단계 예산 상한. 이에 따라 길이와 해상도(15초 720p 75크레딧 / 30초 1080p 390크레딧), 길이가 안 맞을 때 재생성을 허용할지가 정해진다.
