# 실험: 짧은 글이 도달을 높이는가 (cosmicpath)

사전 등록 문서야. 실험이 시작되면 아래 가설, 지표, 글 수, 판정 기준은 바꾸지 않아.

## 근거 (2026-10-16 스냅샷, 관찰 데이터)

재현 방법:
```bash
node --env-file=.env scripts/export-post-metrics.mjs
node scripts/analyze-post-response.mjs .data/analysis/post-metrics-2026-10-16.json --min-age-days=3
```

- 분석 대상 163개 글(측정 시점 3일 이상)의 조회수 중앙값은 123이고, 가장 잘 된 글 하나가 전체 조회수의 47%를 차지해.
- 짧은 글(하위 1/3, 260자 이하)은 기간 보정 후 도달이 1.54배였어. 95% CI는 [1.25, 3.01], BH q는 0.05야.
  - 측정 시점을 7일 이상으로 바꾸면 2.46배 [1.38, 5.00]이고 q는 0.01이야.
  - formula를 self_classification과 그 외로 나눠도 유지돼.
  - 링크 유무로 나눠도 유지돼.
- 하지만 관찰 데이터라서, 짧은 글이 다른 이유(주제, 시기, 공식)로 잘 됐을 가능성을 배제하지 못해. 그래서 무작위 배정으로 확인해.
- 노이즈 기준점: 똑같은 텍스트를 두 번 올린 18쌍의 조회수 차이 중앙값은 1.42배야(p75 1.66배, 최대 4.33배). 글 몇 개로 본 1.5배 이하 차이는 운과 구분이 안 돼.

## 가설

H1: 260자 이하 글(S)은 390자 이상 글(L)보다 발행 7일 시점의 조회수 중앙값이 높다.

## 설계

- **브랜드:** cosmicpath만. cosmicpath-global은 보류해(아래 참고).
- **처치:** 글 길이만 바꿔. S는 260자 이하, L은 390자 이상이야. 261~389자는 실험 기간에 만들지 않아.
- **나머지 조건:** 주제, formula, 링크, 발행 시간은 평소대로 둬. 무작위 배정이 이 차이를 양쪽에 고르게 나눠줘.
- **배정:** 아래 시퀀스를 발행 순서대로 따라. 시퀀스는 seed 20261016으로 만들었고, 2개씩 블록을 지어 S와 L이 각각 45개로 균형이 맞아.
  - 발행에 실패한 글은 시퀀스를 소비하지 않아. 다음에 실제로 발행되는 글이 그 자리를 받아.
- **글 수:** S 45개, L 45개, 총 90개야. 최근 주당 23개를 발행하니까 약 4주 걸려.
  - 검정력: 기간 보정 로그 조회수 표준편차 0.50 기준으로 계산했어.
  - 2배 차이는 약 80% 확률로 잡아.
  - 1.5배 차이는 약 35~40% 확률로만 잡아. 진짜 효과가 1.5배 정도라면 "효과 확인 못 함"이 나올 가능성이 높고, 그걸 감수하는 설계야.
- **중간 확인 금지:** 90개가 다 차기 전에는 판정하지 않아. 결과를 보고 일찍 멈추면 거짓 양성이 늘어나.

```
 1-10: S L L S S L S L S L
11-20: S L L S L S S L L S
21-30: L S S L L S S L L S
31-40: S L S L S L L S L S
41-50: S L L S S L S L S L
51-60: S L L S S L S L S L
61-70: L S S L S L L S L S
71-80: S L L S S L L S L S
81-90: L S L S L S S L S L
```

- **시작 시각(`startAt`):** `2026-10-16T13:34:44.704Z` (KST 2026-10-16 22:34). 판정 때 `--from`에 이 값을 그대로 넣어. 날짜만 넣으면 판정 표본이 어긋나.
  - 기록 근거: `start-length-experiment.mjs` 실행 직후 `--dry-run`을 다시 돌려 "already started"를 확인했어. 운영 배포는 main `904c516`(Vercel Production success, 2026-10-16 12:35 UTC)이야.
- **시작 방법:** 실행 기능(`docs/superpowers/specs/2026-10-16-length-experiment-design.md`)이 배포된 뒤 아래를 실행해. cosmicpath `brandConfig.lengthExperiment`에 시퀀스와 `startAt`이 기록돼. 이미 시작했으면 아무것도 바꾸지 않아.
  ```bash
  node --env-file=.env scripts/start-length-experiment.mjs --dry-run
  node --env-file=.env scripts/start-length-experiment.mjs
  ```
  - 실행 중에는 발행 cron이 슬롯마다 시퀀스의 등급(S/L)에 맞는 실험 초안만 발행해. 맞는 초안이 없으면 그 슬롯은 `length_experiment_waiting_S` 또는 `length_experiment_waiting_L`로 건너뛰어.
  - 실험 대상은 `startAt` 이후 생성된 GROWTH 글이야. 홍보 영상(`video:`) 글과 WARMUP 글은 제외해.
  - 90칸을 다 쓰면 발행과 생성이 평소대로 돌아가.
- 2026-10-27부터 `ref_replay`(외부 구조 재현) 글은 신년 글과 같은 방식으로 실험 대상이 아니다. 시퀀스를 소비하지 않고 판정 표본에도 들어가지 않는다.

## 측정과 판정

1. 마지막 실험 글이 발행된 지 7일이 지나면, `fetch-metrics`가 최근 48시간 안에 돌았는지 확인해.
2. 스냅샷을 새로 뜨고 판정 모드를 실행해:
   ```bash
   node --env-file=.env scripts/export-post-metrics.mjs
   node scripts/analyze-post-response.mjs .data/analysis/post-metrics-<판정일>.json \
     --experiment=cosmicpath --from=<startAt ISO 그대로> --short-max=260 --long-min=390 --planned-n=45 --min-age-days=7
   ```
   - 판정 표본은 `startAt` 이후 처음 발행된 실험 대상 S/L 글 90개야. 그 뒤에 발행된 글은 섞이지 않아. 판정 모드가 이 컷오프와 S·L별 공식 구성을 함께 출력해. 가설과 판정 기준은 그대로야.
3. 판정 기준:
   - **통과:** S가 L의 몇 배인지(도달 배수)의 부트스트랩 95% CI 하한이 1보다 크면 통과야. 이후 생성 기본 길이를 260자 이하로 바꿔.
   - **효과 확인 못 함:** CI가 1을 포함하면 가설을 버리고 다음 가설로 넘어가.
   - **반대 방향:** CI 상한이 1보다 작으면 긴 글이 나은 거야.
4. 참여(첫 댓글을 뺀 좋아요·리포스트·댓글의 1,000뷰당 비율)는 참고용으로만 기록해. 판정에는 쓰지 않아. 지금 유기적 참여가 1건이라도 있는 글이 163개 중 51개뿐이라 신호가 너무 약해.

## 실험 종료 후 체크리스트

**종료 시점:** 시퀀스 90칸을 다 발행한 때야.
- 확인 방법: 진행 확인 명령에서 "실험 표본 90/90"이 나오거나, refill 응답에서 `lengthExperiment` 필드가 사라지면 끝난 거야.
- 이때부터 발행과 생성은 자동으로 평소 동작으로 돌아가.

- [ ] **refill 추가 실행 제거:** `.github/workflows/refill.yml`에서 길이 실험용 cron 2줄(`'13 6 * * *'`, `'13 14 * * *'`)과 그 주석을 지워. 하루 1회로 돌아가서 LLM 비용도 원래대로 줄어.
- [ ] **NEEDS_REVIEW 정리:** 실험 중에는 리뷰하지 않아서 이 초안들이 쌓여 있어.
  - 평소 refill은 이걸 backlog로 세. 그래서 정리하지 않으면 `backlog_full`로 생성이 멈추고, 남은 PENDING을 다 쓰면 발행도 멈춰.
  - 승인하거나 보관 처리해.
- [ ] **남은 PENDING 확인:** 남은 초안은 평소 순서대로 발행돼. 원하지 않는 글은 보관해.
  - 실험 시작 전에 만든 초안(실험 중에는 발행되지 않았어)
  - 실험용으로 만들었지만 남은 L 초안(400~450자)
- [ ] **판정:** 마지막 실험 글이 발행되고 7일이 지나면, 위 "측정과 판정" 절차대로 판정해. `--from`에는 `startAt`(`2026-10-16T13:34:44.704Z`)을 그대로 넣어. 실험 종료 후 발행된 글은 컷오프로 빠지니까, 판정 전까지 평소대로 운영해도 돼.
- [ ] **결과 기록:** 판정 출력을 이 문서 아래에 붙이고 커밋해. 기록할 것은 다음과 같아.
  - 도달 배수와 95% CI
  - S·L별 공식 구성
  - 실험 표본 개수
- [ ] **결과에 따른 조치:**
  - **통과:** 260자 이하를 생성 프롬프트, 스크립트, 캠페인, 발행 게이트 등 모든 경로에 강제해.
  - **효과 확인 못 함 / 반대 방향:** 길이 방침은 강제하지 않고 다음 가설로 넘어가.
- [ ] **실험 설정은 지우지 않아도 돼:** `brandConfig.lengthExperiment`는 시퀀스를 다 쓰면 자동으로 꺼져. 판정 근거로 남겨둬.
- [ ] **미뤄둔 작업 처리:** 실험 중에는 길이에 영향을 줘서 미뤘던 것들이야.
  - 발행 글의 마크다운 기호 정리(끝에 남은 `---`, `#` 제목, `**`)
  - `scripts/publish-one-global.ts`가 안전 게이트를 우회하는 문제
  - 시작 전 초안이 발행 후보 50개 창을 차지하는 문제

## 실험 밖에서 발견한 것 (조치 후보, 이 실험의 범위 아님)

- **프롬프트 유출:** 2026-09-30 글이 생성 지시문 그대로 발행됐어("자기분류 셀프체크형 포스트입니다… **본문 (482자)**"). 2026-09-04 global 글도 "# Threads Post:" 제목 줄이 붙은 채 나갔어. 발행 게이트의 메타 텍스트 패턴이 좁았던 게 원인이야.
  - **수정:** `fix/meta-text-leak` 브랜치. 발행 게이트에 패턴 3개를 추가했어.
- **학습 루프의 승자 선정:** 글 2개 이상에 평균 점수 기준이라, 대박 글 하나에 끌려가.
  - `controversy_stunt`는 42,329회와 115회 두 글이야.
  - `저장 검증 CTA`는 평균 6,123회지만 중앙값은 79회야.
  - `링크 확인` CTA는 도달 0.45배 [0.25, 0.96]로 더 낮은데도 승자 목록에 있어. 이 목록은 `optimizationGoal`이 배포되기 전 코드가 클릭 가중 점수로 계산한 거야.
  - 이 목록이 생성 프롬프트에 "잘 먹힌 패턴"으로 들어가고, 자동 승인과 공식 샘플링 가중치에도 쓰여.
  - **수정:** `fix/growth-winner-noise` 브랜치. 승자, 약점, 자동 승인 공식, 가중치를 모두 글 5개 이상 + 중앙값 기준으로 판정하게 바꿨어.
